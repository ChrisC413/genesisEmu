# M05-03 · YM2612 FM synthesis (ymfm)

**Milestone:** [M05 – Audio](README.md)  
**Status:** Implemented; listening comparison pending (Chris)  
**Depends on:** M05-01  
**Spec refs:** [06-audio](../../docs/specs/06-audio.md#ym2612-fm)

## Story

As a **developer**, I want YM2612 FM synthesis using ymfm behind an `IFmSynth` interface, so that music sounds right without writing an FM core from scratch.

## Scope

- Integrate `ymfm::ym2612` (vcpkg or vendored in `third_party/` with license notice)
- `IFmSynth`: write/read_status/generate/serialize
- Register port interface (A0/D0/A1/D1), busy flag
- Catch-up clocking at MCLK/7

## Acceptance criteria

- [ ] Sonic 1/2/3K title music matches reference recordings by ear and within tolerance in the WAV comparison
- [x] FM state round-trips through save states
- [x] ymfm license listed in `THIRD_PARTY_NOTICES.md`

## Test plan

- WAV comparison tests
- Save-state round-trip test

## Notes

- ymfm is not in the pinned vcpkg baseline, so it is vendored unmodified in `third_party/ymfm/` (only the
  OPN sources; commit `81aec25c`), built as a warning-free static library and listed in
  THIRD_PARTY_NOTICES. `tools/format.py` skips `third_party/`.
- `IFmSynth` / `makeYmfmSynth()` (src/core/audio/fm_synth.*). A thin subclass of `ymfm::ym2612` reproduces its
  output stage with a channel mask for mute / solo.
- Save states: `serialize()` / `deserialize()` round-trip (unit test replays identical samples). The state
  hash covers the serialized chip. Save-state files themselves arrive in M06.
- Unit test: a single-operator voice programmed for 440 Hz plays at 440 Hz +-1%.
- Title-screen WAVs (scratch only): Sonic 1, Sonic 2 and S3K title music at -20 to -25 dBFS RMS with no
  clipped samples.
- **Not verified:** "matches reference recordings by ear and within tolerance in the WAV comparison". There
  are no reference captures in the repository (spec 06 wants tolerance-based comparison against another
  implementation's output); left for Chris.
