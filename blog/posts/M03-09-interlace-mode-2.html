Double resolution for two players

Sonic 2's split-screen mode squeezes two full views into one screen by switching the VDP into interlace mode 2. The emulator has to draw 448 lines from two alternating fields.

genesisEmu build notes4 min readStory M03-09

Sonic 2 introduced a two-player mode with the screen split horizontally. The obvious approach, giving each player 112 lines, would squash the playfield to half height. Sonic 2 instead uses a rarely used VDP feature, interlace mode 2, which doubles the vertical resolution to 448 lines. Each player gets 224 lines, the same as single-player, just at half the line height. Decision D-003 calls this out: Sonic 2 requires interlace mode 2, so the emulator has to implement it.

What interlacing is

A standard-definition TV draws a frame as two fields: first the even lines, then the odd lines, slightly offset. Most consoles ignore this and draw the same lines in both fields (a "240p" picture). Interlace mode 2 makes the VDP draw different content in each field, so the two fields together form a 448-line picture. The cost is that each field shows only half the lines, so the picture appears to flicker on a real TV.

What changes in the VDP

Turning on mode 2 (register 12) changes several things at once:

  • Tiles become 8×16, 64 bytes each instead of 32. Name-table entries now index double-height tiles.
  • Y coordinates double. Planes are addressed in 448-line space, the vertical scroll grows to 11 bits, and sprites use a 10-bit Y with an offset of 256 instead of 128.
  • The VDP renders one field per frame, alternately the even and the odd lines, and the odd-frame bit in the status register toggles every frame so the game knows which one it is.

In the renderer, each of these is a small parameter switch rather than a separate code path. The plane, window and sprite renderers all take their tile height, tile size and Y offset from the mode:

Each frame draws half the lines. The other half stay from the previous frame, woven together into a 448-line picture.

Weaving two fields

The framebuffer has room for 480 lines. In mode 2, each rendered line goes to row 2 × line + field, where the field alternates every frame. The rows of the other field are left alone, so they still hold the previous frame's content. The two together form the full picture. This is called weave deinterlacing:

Interlace mode 1, which shows the same content in both fields, is rendered progressively, since there's nothing to weave. The VDP's HV counter in both interlace modes follows the tables from M03-03.

Showing it at the right size

A 448-line frame shouldn't appear twice as tall as a normal one. The game view (M03-10) treats a mode-2 frame as having half the lines when it computes the picture size, so the split-screen picture fills the same area as single-player, at double the vertical detail.

Verified without a menu

The acceptance criterion imagined reaching two-player mode through a save state or scripted input, both of which came later. It turned out to be unnecessary. Sonic 2's attract sequence includes a two-player Emerald Hill demo that switches to interlace mode 2 by itself. Both halves render in a 320×448 frame, with title cards, both HUDs, Sonic and Tails. Frames 1,400 and 2,000 of that demo are golden checkpoints. A unit test, Interlace mode 2: 8x16 tiles, 448-line frames, one field per frame, checks the tile layout, the doubled coordinates and the field alternation with synthetic VRAM.
