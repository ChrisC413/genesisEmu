FM synthesis, borrowed on purpose

The YM2612 gives the Genesis its sound. Instead of writing an FM synthesizer from scratch, genesisEmu wraps ymfm, a well-regarded BSD-licensed implementation, behind a narrow interface.

genesisEmu build notes4 min readStory M05-03

The Yamaha YM2612 is where the Genesis gets its sound: six channels of FM synthesis, each built from four operators, sine-wave oscillators that modulate each other's phase in one of eight arrangements. It's capable of anything from bright brass to metallic bass, and getting it exactly right involves envelope generators, a low-frequency oscillator, quirky rounding in its output stage and undocumented edge cases that took the emulation community years to map out.

The project made a deliberate choice about it. Decision D-013: YM2612 via ymfm (BSD-3) behind IFmSynth. The hand-written requirement applies to the CPUs, where reverse engineering needs total control and instrumentation. For the FM chip, ymfm, Aaron Giles's library of Yamaha FM cores, is accurate and permissively licensed. Writing a second YM2612 from scratch would have taken a lot of effort for no gain in the project's goals.

Vendored, unmodified

ymfm isn't in the vcpkg baseline the project pins, so its OPN sources are vendored unmodified under third_party/ymfm/ at a recorded commit. They're built as a separate static library that compiles warning-free, skipped by the project's clang-format check, and listed in THIRD_PARTY_NOTICES.md with the full BSD-3 licence text, which was one of the acceptance criteria.

A narrow interface

The rest of the emulator never sees ymfm. It talks to IFmSynth: write a register port (the YM2612's four ports A0/D0/A1/D1), read the status, generate N samples, and serialise or restore the chip. makeYmfmSynth() is the only place that knows which implementation is behind it. If a different FM core is ever wanted, for comparison or for speed, it's one class to replace.

Catch-up, one sample at a time

The sound system follows the same lazy pattern as the Z80 (M04-07). It doesn't run continuously; it's brought up to date when something needs it. That happens at the end of every scanline, and also immediately before any CPU reads or writes a sound-chip port, so a write lands at exactly the right sample:

The YM2612 is clocked from the 68000's clock (master clock ÷ 7) and produces one sample every 144 of its own clocks. That works out to one stereo sample every 1,008 master clocks, the native rate of about 53,267 Hz that the whole audio path from M05-01 is built around.

The CPUs are hand-written because reverse engineering needs complete control of them. For the FM chip, a proven library was the better engineering choice.

Muting channels without forking the library

For reverse engineering, being able to mute or solo individual FM channels is essential (M05-05). ymfm's generate mixes all channels internally. Instead of modifying the vendored sources, genesisEmu derives a small class, MaskedYm2612, that reproduces ymfm's YM2612 output stage, including the "DAC discontinuity" quirk of the real chip's output, but only adds up the channels in a mask. A muted channel contributes exactly what a silent channel would.

Save states

The interface's serialize() and deserialize() wrap ymfm's own save/restore, extended with the timer and busy-flag state that genesisEmu tracks itself. A unit test serialises a playing chip, restores it into a fresh one, and requires both to produce identical samples from then on. Save-state files come with M06; the state hash already covers the serialised chip.

Checked by measurement, waiting for an ear

A unit test programs a single-operator voice for 440 Hz and checks, by counting zero crossings, that it plays at 440 Hz within 1%. Title-screen recordings of all three games (kept as scratch files, never committed) came out at −20 to −25 dBFS RMS with no clipped samples.

The main criterion, Sonic 1, 2 and 3K title music matches reference recordings by ear and within tolerance in a WAV comparison, is open. The repository holds no reference recordings, which would come from another implementation or from hardware, and nobody had listened yet. The story says so: "Implemented; listening comparison pending (Chris)".
