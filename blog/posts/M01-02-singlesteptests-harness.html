A million tests before breakfast

The SingleStepTests suite records what a real 68000 does for each instruction. genesisEmu checks itself against all of it in about three seconds.

genesisEmu build notes5 min readStory M01-02

How do you know a CPU emulator is right? Running a game and checking that it looks fine is a weak test. Games use a fraction of the instruction set and tolerate many small errors. Writing your own tests by reading the manual only checks your reading of the manual.

The SingleStepTests project offers something better: for the 68000, about a million recorded test vectors. Each vector gives a complete initial state (registers, the prefetch queue, the relevant bytes of memory), runs one instruction, and gives the expected final state and the exact number of clock cycles. If an emulator matches all of them, it behaves like the reference across the instruction set, including the odd corners.

M01-02 built the harness that runs those vectors. Everything else in the milestone was developed against it.

Getting the data without committing it

The suite is large: 124 files and 202.6 MB of gzipped JSON. It also has no LICENSE file, so it can't be vendored into an MIT repository. tools/fetch-test-data.py downloads it on demand, pinned to a specific commit (e0d5ece9), and checks every file against the git blob SHA-1 recorded in tools/test-data.lock.json. A file whose hash changed upstream is rejected, not silently used.

Parsing 200 MB of JSON in a C++ test would be slow and would need a JSON parser in the test binary. The fetch script converts each file once into a compact binary .sst format, about 250 MB in total, that the runner streams with a few lines of code:

Each converted file records the hash of the JSON it came from, so a stale conversion is detected and re-run.

Running one vector

For each vector the runner loads the initial RAM bytes into a flat 16 MB bus, sets the CPU state, calls step() once and compares. It checks all registers, both stack pointers, the status register, the program counter, both prefetch words and every expected RAM byte. It also checks for writes the vector didn't expect, so a spurious write to the wrong address fails even if every expected byte is right.

Instead of clearing 16 MB between vectors, the bus remembers which bytes were loaded or written and zeroes only those. That keeps a million vectors in the range of seconds.

The Release CI job runs all 1,000,060 vectors on every push. It takes about three seconds.

Reports you can act on

The output is one line per file: passed, total, state mismatches, cycle-only mismatches and excluded vectors. The split between "state" and "cycle-only" matters during development. A cycle-only mismatch means the instruction computed the right result but took the wrong time, a different kind of bug from a wrong flag.

With --show N the runner prints the first N failures in full: the initial registers and every field that differs, written as expected!=actual. --failures FILE writes every failure to a file for grepping. --only MOVE.w,ADD.l restricts a run to the files you're working on.

Exclusions need a reason

A handful of vectors disagree with the 68000 manual or are corrupt. Silently skipping them would hide regressions, and "fixing" the core to match them would make it wrong. The harness reads tests/m68k/sst_exclusions.txt, in which every excluded vector sits under an @ line that states the reason:

By the end of the milestone the file held 3,738 entries with two reasons, out of just over a million vectors.

Testing the tester

A harness that always passes is useless. The self-test m68k.sst_selftest runs the NOP vectors with --inject-fault, which flips a bit of D0 after every NOP, and with --expect-fail, which inverts the exit code. If the harness ever stops detecting a corrupted register, CI goes red.

In CI: everything, every push

The story planned a fast subset per push and a full nightly run. In practice the full suite was quick enough to need no nightly job. The Release job runs all 1,000,060 vectors on every push in about three seconds, and the Debug job runs the first 250 vectors of each file. The converted data is cached by the hash of the lock file. If the data is missing, the runner exits with code 4, which CTest reports as skipped rather than passed.

What the suite doesn't cover

The story notes record the suite's blind spots. Every vector starts in supervisor mode with interrupt mask 7, SSP at $800 and the trace bit clear. User mode, privilege violations, tracing, interrupts and STOP are therefore covered by hand-written unit tests in the later stories.
