Eighty sprites, twenty per line

Sonic, rings, badniks and the HUD are hardware sprites. The VDP walks a linked list of them every line, runs out of time and drops the rest, and genesisEmu has to drop exactly the same ones.

genesisEmu build notes4 min readStory M03-07

Everything that moves independently of the background (Sonic himself, rings, enemies, the score) is a sprite. The VDP supports up to 80 of them in the 320-pixel mode and 64 in the 256-pixel mode, each from 1×1 to 4×4 tiles in size. But the hardware has a fixed amount of time per scanline to fetch sprite data, so it imposes per-line limits. When too many sprites share a line, some disappear. Games that rotate their sprite order each frame turn that into the familiar flicker. M03-07 implemented sprites with those limits, because games are designed around them.

A linked list, not an array

Sprites are described in the sprite attribute table in VRAM, 8 bytes per sprite: Y position, size, a link to the next sprite, the tile index with flips, palette and priority, and the X position. The VDP doesn't scan the table in order. It starts at sprite 0 and follows the link fields until a link of 0. Games use the links to control drawing order, which is also priority order among sprites: earlier in the list wins.

The first four bytes of each entry (Y, size and link) don't come from VRAM at render time. They come from the VDP's internal sprite cache from M03-01, which updates only when the CPU writes into the table. The renderer reads the rest (tile, flips, palette, X) from VRAM.

Two passes per line

The renderer works the way the hardware does: first evaluate, then draw.

Evaluation walks the link list and collects the sprites that cover the current line, up to 20 in H40 mode (16 in H32). Finding a 21st sets the overflow flag and stops:

Drawing fetches each found sprite's pixels for this line, 8 at a time, against a second limit: 320 sprite pixels per line in H40 (256 in H32). A wide sprite late in the list can be cut off part-way when the pixel budget runs out. Earlier sprites are drawn first and win: a pixel already set in the sprite line buffer isn't overwritten.

Missing sprites aren't a bug in the emulator. The hardware runs out of time on a scanline, and games are designed around it.

The masking rule

The odd part of sprite handling is masking. A sprite whose X coordinate is exactly 0 (that is, −128 on screen, entirely off the left edge) can hide all lower-priority sprites on the rest of its lines, which lets a game cut sprites off at an invisible boundary. The rule has conditions, and the renderer implements them as documented in the story: the mask takes effect once a sprite with non-zero X has been seen on that line, or if the previous line ran out of sprite pixels.

Masked sprites still count against the pixel budget, as on hardware. They take time even though nothing is drawn.

Status flags

Two status-register bits come from sprites. Overflow is set when a line hits either limit. Collision is set when two opaque sprite pixels land on the same spot. Both clear when the status register is read. The collision flag doesn't say which sprites collided, which limits its use, but it's cheap to emulate.

Sizes and flips

A sprite of W×H cells stores its tiles column by column: the first H tiles are the left column, the next H the second, and so on. Horizontal flip reverses the column order as well as the pixels within each tile; vertical flip reverses the rows. Interlace mode 2 (M03-09) doubles tile height and changes the Y offset from 128 to 256.

Verified

A synthetic unit test covers the link list, sizes, flips, per-line limits, masking and collision. One part puts 21 sprites on one H40 line and checks that the 21st is dropped and the overflow flag is set; the story originally asked for a test ROM for that. For the games, dumped frames were checked by eye across all three titles: Sonic, Tails and Knuckles, rings, badniks, the HUD and title-screen sprites in Sonic 1's Green Hill demo, Sonic 2's Emerald Hill (two-player), Chemical Plant and Aquatic Ruin demos, and Sonic 3 & Knuckles' Angel Island intro and demo. Several of those frames are golden checkpoints.
