A disassembler that proves itself with an assembler

Turning machine code back into text is easy to get almost right. genesisEmu's disassembler is checked by reassembling 196,608 instructions and comparing every byte.

genesisEmu build notes4 min readStory M01-12

A disassembler turns machine code bytes back into readable assembly. For a reverse-engineering tool it's the main way of seeing code. The debugger shows it at the program counter, the tracer writes it into logs, and the later analysis milestones aim to produce a full disassembly of each Sonic game that reassembles bit-identically to the original ROM (decision D-005).

That last goal set the bar for M01-12. "Looks right" isn't enough. The output must be text that a real assembler turns back into exactly the same bytes, for every instruction.

Speaking AS

The project targets The Macro Assembler AS (D-010), the open-source cross-assembler used by the community Sonic 2 and Sonic 3 & Knuckles disassemblies. The disassembler therefore emits AS's dialect of Motorola syntax, with a few deliberate conventions spelled out in its header:

  • Explicit sizes wherever AS accepts them: move.w, lea.l, bra.s, dbf.w. Without a size, an assembler picks its own, perhaps a shorter branch than the original, and the bytes change. AS rejects a suffix on a few instructions (such as swap, jmp, jsr, trap, stop), and those are emitted without one.
  • PC-relative operands print the target address, not the raw displacement: lea.l $00001004(pc),a0. AS computes the displacement itself, and the text stays meaningful when code is moved.
  • abs.W prints sign-extended: ($FFFF8000).w, because that is the address the CPU actually uses.

More than text

Each call returns an Instruction with the text, the length in bytes, a flow type (fallthrough, branch, conditional branch, call, return, indirect jump or call, trap, stop or invalid), the static target when one is known, and a list of every absolute address the instruction references. Code-discovery tools need exactly these to follow execution paths through a ROM and to find the data tables code points at.

If an encoding can't be reproduced byte for byte by the assembler, it's emitted as data. The round trip always wins over readability.

When the honest answer is dc.w

Some valid machine code has no faithful text form. A 68000 ignores certain bits in an index extension word that the 68020 later used, so two different byte sequences can mean the same instruction, and an assembler can only produce one of them. Byte immediates are stored in a word with an ignored high byte. A MOVEM can have an empty register list, which has no syntax at all. For every such case the disassembler emits the raw word as data, for example dc.w $0000, and marks the instruction invalid. The reassembled ROM stays identical, which matters more than prettier output.

Decoding separately from the CPU, on purpose

The disassembler could have reused the CPU core's decode table. It doesn't. It lives in gen_analysis with its own decoder, so that a bug in one isn't automatically copied into the other. A unit test keeps the two in agreement over all 65,536 possible first words:

The round trip

The strongest test is gen_disasm_roundtrip, run by CTest as analysis.disasm_roundtrip:

  1. Build a corpus from every 65,536 first words, each followed by three different sets of extension words: small positive values, negative displacements and high addresses, and byte-sized values. That's 196,608 instructions.
  2. Disassemble each one at its address in the corpus and write the text into one big assembly file.
  3. Assemble the file with AS, convert the output to a flat binary with AS's p2bin, and compare every byte with the corpus.
  4. Check that every valid first word came out as a real instruction, not dc.w, in at least one of the three sets.

The result: 196,608 instructions (136,765 decoded, 59,843 emitted as dc.w), 505,282 bytes, zero mismatches. AS itself (version 1.42, build 315) is downloaded and SHA-256-pinned by the same fetch-test-data.py script as the CPU test vectors. A Windows binary is fetched; on other platforms you point GENESIS_ASL at your own build, and without AS the test reports skipped rather than passing.

Where it's used

The disassembler went into service in the next milestone. M02's instruction tracer prints every executed instruction through it. The planned debugger disassembly view and ROM-map analysis will build on the same library. The Z80 got a matching disassembler in M04, also checked by a round trip through AS.
