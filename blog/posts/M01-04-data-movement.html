Moving data, in exactly the right order

MOVE looks like the simplest instruction there is. Getting it bit-exact meant matching the order of the chip's microcode.

genesisEmu build notes5 min readStory M01-04

Most of what a game's CPU does is move data: copy a sprite's position into a table, load a pointer, push registers before a subroutine, clear a variable. The 68000 has a family of instructions for this, and M01-04 implemented all of them: MOVE, MOVEA, MOVEQ, MOVEM, MOVEP, LEA, PEA, EXG, SWAP, LINK, UNLK and CLR.

The result was 100% of 153,235 SingleStepTests vectors across 19 files, cycle counts included. The interesting part is what it took to get there, because "copy A to B" turned out to have hidden structure.

When does MOVE write?

For correct output, all MOVE needs is to read the source, write the destination and set the N and Z flags. But in the word and long test files, 35–58% of the vectors involve an address error, an odd address somewhere in the operation. When that happens the 68000 stops mid-instruction and records what it was doing. So the emulator must stop at the same point: after the same reads, the same writes and the same prefetches, with the registers half-updated in the same way.

A long write to -(An) has a quirk of its own. It writes the low word first, decrementing An by 2 before each half. If the second half faults, An is left 2 lower than where it started, and the core has a dedicated helper, writePreDecLong, to reproduce it.

In the word and long files, up to 58% of the vectors involve an address error. To pass them, the emulator has to stop at the same point inside the instruction as the real chip.

MOVEM: a bitmask of registers

MOVEM saves or restores any subset of the sixteen registers in one instruction. Subroutines start with movem.l d0-d7/a0-a6,-(sp) and end with the reverse. The subset is a 16-bit mask in the extension word, and the mask's bit order flips for the pre-decrement form. Normally bit 0 is D0 and bit 15 is A7. With -(An), bit 0 is A7 and bit 15 is D0, because the registers are stored downwards from the top:

Loading has its own details. A word-sized MOVEM into registers sign-extends each value into all 32 bits, data registers included, unlike MOVE.W, which leaves the upper half alone. And the 68000 reads one extra word after the last register, which costs time and can fault. Both are in the code because the suite checks both.

MOVEP: built for 8-bit peripherals

MOVEP is an odd instruction. It transfers a register's bytes to every other address: base, base+2, base+4... It was designed for 8-bit peripheral chips wired to only one half of the 16-bit data bus. The implementation is a simple loop, high byte first:

Small instructions, small surprises

  • CLR reads before it clears. On the 68000, CLR to memory performs a read cycle first, then the write. It looks wasteful, but it costs time and can trigger read side effects on hardware registers, so the core does it too.
  • MOVEA doesn't touch flags. Moves into address registers leave the condition codes alone and sign-extend word sources to 32 bits.
  • MOVEQ packs a signed 8-bit constant into the opcode itself and sign-extends it into the full register. It's the fastest way to load a small number, and it is extremely common in 68000 code.
  • LEA and PEA only accept "control" addressing modes (no registers, no post-increment) and pay 2 extra internal cycles for the indexed forms. PEA with an absolute address pushes before the final prefetch; with other modes it prefetches first.
  • LINK and UNLK build and tear down stack frames: push An, copy SP into An, add a displacement to SP.

How it was verified

Each instruction family has its own SingleStepTests files: MOVE.b/w/l, MOVE.q, MOVEA.w/l, MOVEM.w/l, MOVEP.w/l, LEA, PEA, EXG, SWAP, LINK, UNLINK and CLR.b/w/l. All 153,235 vectors pass, including every address-error variant and every cycle count. When a vector failed, the runner's diff (expected versus actual register by register, plus the cycle count) usually pointed straight at an ordering difference, and fixing it became one more line of microcode-order knowledge in the handlers.
