Supervisor mode and the status register

Interrupt masks, privilege, two stack pointers and an instruction that halts the CPU until something happens. This is the part of the 68000 an operating system would use, and Genesis games use it too.

genesisEmu build notes4 min readStory M01-09

The 68000 was designed for multi-user systems, so it has two privilege levels. In supervisor mode code can do anything. In user mode some instructions are forbidden and trap instead. Genesis games mostly run in supervisor mode the whole time, but they still use this machinery constantly. Every game masks and unmasks interrupts while it updates video memory, and that goes through the status register.

M01-09 implemented the instructions that touch it: MOVE to and from SR and CCR, MOVE to and from USP, ANDI/ORI/EORI to CCR and SR, STOP and RESET.

The status register

The low byte, the CCR, holds the condition codes and anyone may change it. The high byte holds the trace bit, the supervisor bit and the three-bit interrupt mask, and only supervisor code may change it. A game typically writes move.w #$2700,sr to block every interrupt, does something timing-sensitive, then lowers the mask again.

Flipping S swaps stacks

The 68000 has two stack pointers, the user stack pointer (USP) and the supervisor stack pointer (SSP), and A7 always shows whichever is active. The last line is another hardware detail. After writing the status register the 68000 discards and refills its prefetch queue, which costs time, and the suite's cycle counts show it.

The test suite never leaves supervisor mode, so everything about user mode had to be tested by hand.

STOP: sleep until an interrupt

STOP #imm loads the status register from its operand and halts the CPU until an interrupt arrives that the new mask allows. The core sets a stopped flag. While it's set, step() returns 4 idle cycles per call and reports Flow::Stopped, so the machine around the CPU keeps running and the debugger can tell the CPU is waiting rather than executing. When an interrupt above the mask arrives, the interrupt path clears the flag.

RESET: a pulse on a wire

The RESET instruction doesn't reset the CPU. It pulses the external reset line so that the other chips on the board reset. In the core it calls Bus68k::resetDevices(), leaving the system bus to decide what that means for the Genesis, and costs 132 cycles in total.

Testing what the suite can't reach

The story notes record a gap. SingleStepTests has no STOP file, and every vector starts in supervisor mode. Everything about user mode therefore needed hand-written unit tests in tests/unit/m68k_test.cpp:

  • Privileged instructions trap in user mode and stacks switch: MOVE #$0000,SR drops to user mode, and A7 must now show the USP. The next MOVE #$2700,SR must trap through vector 8, with a six-byte frame on the supervisor stack whose PC is the privileged instruction.
  • STOP waits for an interrupt above the mask: STOP #$2300 sets mask 3. A level-2 interrupt leaves the CPU stopped; level 4 wakes it, it vectors to the level-4 handler, and the stacked PC points after the STOP.
  • RESET pulses the external reset line: the test bus counts resetDevices() calls and the step must take 132 cycles.

For everything the suite does cover (MOVE from SR, MOVE to SR and CCR, MOVE to and from USP, the immediate logic ops on CCR and SR, and RESET) the core passes 100% of 96,780 vectors with exact cycles.
