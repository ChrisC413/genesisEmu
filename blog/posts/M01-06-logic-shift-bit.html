Bit twiddling, and a disagreement with the reference

Logic ops, shifts, rotates and bit tests pass 359,187 vectors. For 3,736 more, the project sided with the manual against the test suite.

genesisEmu build notes5 min readStory M01-06

Games run on bit twiddling. Collision flags are packed into bytes, object status lives in individual bits, controller input arrives as a bitmask, and multiplying by a power of two is a shift. M01-06 covers the 68000 instructions that do this: AND, OR, EOR and NOT with their immediate and status-register forms, all eight shifts and rotates, the bit instructions BTST, BSET, BCLR and BCHG, plus TST, TAS and Scc.

Shifts, one bit at a time

The 68000 has four families of shift, each in both directions: arithmetic (ASL/ASR, which keep the sign), logical (LSL/LSR), rotate (ROL/ROR) and rotate through extend (ROXL/ROXR, where the X flag acts as a 17th, 9th or 33rd bit). Counts can come from the instruction (1 to 8) or from a register, modulo 64, which is more than the operand size.

The flags differ in small ways between families. ASL sets V if the sign bit changed at any point during the shift. A rotate never touches X. ROXL with a count of zero copies X into C. Rather than finding a clever closed form for each, the core shifts one bit at a time, exactly as the description in the manual reads:

A loop of up to 63 iterations sounds slow, but large register counts are rare in real code, and the loop matches the hardware's own timing model: 2 cycles per bit shifted. That's in the handler too: c.idle((S == 4 ? 4 : 2) + 2 * static_cast<int>(count)).

When the reference and the manual disagree, the project has to choose, and then write the choice down.

The ASR disagreement

Here the suite and the core part ways. Take ASR (arithmetic shift right) on a negative byte, shifted by a register count greater than 8, say 20. An arithmetic right shift copies the sign bit back in, so the value fills with ones, and every bit shifted out after the first few is a 1. The manual says C is "set according to the last bit shifted out", so C and X should end up 1.

For these cases the SingleStepTests suite expects C = X = 0. The core follows the manual (and Musashi, the long-established 68000 emulator, agrees with the manual). The 3,736 affected vectors are listed in tests/m68k/sst_exclusions.txt under a paragraph explaining why, with the exact selection rule: ASR Dn,Dy with (Dn & 63) > size and the operand's MSB set. Two more ASL.b vectors are excluded as corrupt: their expected D2 differs in all 32 bits, which a byte shift can't produce.

The exclusion is a decision, recorded where anyone can audit it. If later evidence from real hardware favours the suite, changing the core is a few lines and deleting the exclusions.

Bit numbers wrap differently by destination

BTST and its siblings take a bit number from an immediate or a register. If the target is a data register, the number is taken modulo 32. If it's memory, the operation is byte-sized and the number is taken modulo 8. One handler covers both, templated on the destination mode. The suite also confirmed one timing detail: BTST with an immediate bit number on a register takes 10 cycles.

TAS: a Genesis quirk

TAS, "test and set", reads a byte, sets the flags from it, and writes it back with bit 7 set, as one indivisible read-modify-write bus cycle. It was made for multiprocessor locks. On the Genesis the write half of that locked cycle doesn't reach the cartridge or RAM, so memory is left unchanged. The CPU spec lists this as quirk C68-9: "TAS write-back is ignored on the cartridge/RAM bus".

Write-back is off by default, which is correct for the Genesis. The SingleStepTests runner turns it on, because the suite models a normal 68000 bus. A unit test, TAS write-back is configurable (Genesis quirk), covers both settings. A few commercial Genesis games are known to rely on this quirk, so the emulator has to get it right even though the test suite can't check it.

Scc and the logic ops

Scc writes $FF or $00 to a byte depending on a condition, a branch-free way to turn a flag into a value. The logic instructions set N and Z from the result and clear V and C through the same helper MOVE uses, setLogicFlags. Their immediate forms with CCR or SR as the destination are how code changes flags or the interrupt mask directly. The SR forms are privileged, which M01-09 handles.

The numbers

Across 45 files, covering AND, OR, EOR, NOT and TST in all sizes and forms, every shift and rotate, BTST/BCHG/BCLR/BSET, TAS and Scc, the core passes 100% of the 359,187 vectors that aren't excluded, cycles included. The exclusions are 3,736 ASR vectors where the project followed the manual and 2 corrupt ASL.b vectors.
